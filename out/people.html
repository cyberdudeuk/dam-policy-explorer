Roles and journeys

Who takes part in the DAM Policy, what each person needs, and the route through this app and the playbooks that fits their role.

The roles and user stories come from the DAM capability playbooks (opens in a new tab), and the questions from the GDS question register. They still need testing with real users. Suggested practice

  • Lead policy coordinator
  • Chief data officer
  • Data owner
  • Data steward
  • Catalogue manager or data custodian
  • Data quality lead or analyst
  • Programme or project lead
  • Commercial or technology lead

Lead policy coordinator

Coordinates adoption day to day, collates and assures the return, and represents the organisation at the Working Group.

Context

Works across many teams, often alongside another role. Needs one route from start to return, and templates to reuse.

Goals

  • Get the Baseline Return right first time
  • Avoid retyping information that already exists
  • Keep arm's length bodies in step

User stories

  • As a lead policy coordinator, I need one ordered route from mobilising to an assured return, so that nothing is missed and nothing is done twice.
  • As a lead policy coordinator, I need templates that match what GDS asks for, so that the return is collation, not reconstruction.

What gets in the way

  • Requests arrive from several directions with different deadlines
  • Owners change and nobody updates the record

Success looks like: An assured return goes in on time, built from catalogue records rather than retyped.

Journey

  1. 1. Learn
    • The policy in plain English
    • The four scope principles
  2. 2. Prepare
    • Name who is in charge, set up arm's length body contacts
    • Build the candidate list
  3. 3. Do
    • Test each asset
    • Confirm owners and fill in the details
  4. 4. Report
    • Check the list
    • Assure arm's length body returns, sign off and send
  5. 5. Improve
    • Schedule the annual review
    • Share what you learned

Chief data officer

Accountable for adopting the policy across the organisation and, in a department, its arm's length bodies.

Context

Has little time, decides on resourcing and reports progress to the Chief Data Officer Council. Wants summaries first, detail on request.

Goals

  • Adopt the policy once, without the three capabilities duplicating effort
  • Know the organisation's position at any time
  • Show credible progress to the CDO Council

User stories

  • As a chief data officer, I need to see what the policy requires and who does what, so that I can assign the work with confidence.
  • As a chief data officer, I need a short, current view of progress, so that I can unblock problems before the return is due.

What gets in the way

  • Governance, cataloguing and quality teams record the same facts in different places
  • Evidence is assembled in a rush at the deadline

Success looks like: Every critical data asset has a named owner, a current catalogue record and a quality plan, and the return goes in on time.

Journey

  1. 1. Learn
    • What you must do
    • Who does what
  2. 2. Prepare
    • Name your coordinator
    • Agree how owners are named
  3. 3. Do
    • Resourcing: what GDS expects
  4. 4. Report
    • Sign off the return
  5. 5. Improve
    • Make it business as usual

Data owner

The senior leader accountable for the meaning, content, quality and management of one or more critical data assets.

Context

Data ownership is one of several responsibilities. Makes decisions and signs off; others do the day-to-day work.

Goals

  • Understand exactly what they are accountable for
  • Make decisions quickly with the right evidence
  • Name a successor so the asset is never orphaned

User stories

  • As a data owner, I need a clear list of the decisions that are mine, so that I can sign off with confidence.
  • As a data owner, I need to see how good my data is and what it should not be used for, so that I can accept or reject risks knowingly.

What gets in the way

  • Unclear difference between data owner and information asset owner
  • Asked to sign things without the context

Success looks like: Can explain the assets' purpose, quality and risks, and a successor is named.

Journey

  1. 1. Learn
    • Data owner and information asset owner
  2. 2. Prepare
    • Accept the role
  3. 3. Do
    • Agree a quality plan
  4. 4. Report
    • Partial progress: report it honestly
  5. 5. Improve
    • Review every year

Data steward

Runs critical data assets day to day: their standards, access, metadata and quality processes.

Context

Does the detailed work and keeps the records current. Needs step-by-step methods and templates.

Goals

  • Keep the catalogue record and quality plan current without heroics
  • Find problems before users do
  • Hand over cleanly when moving on

User stories

  • As a data steward, I need step-by-step instructions with templates, so that I can do the work consistently across assets.
  • As a data steward, I need one place to record each fact once, so that the catalogue, the quality plan and the register always agree.

What gets in the way

  • The same owner and review date recorded in three places
  • Quality rules kept only in one tool

Success looks like: Every asset stewarded has a current record, rules with targets, and a quality statement users understand.

Journey

  1. 1. Learn
    • Mandatory metadata
  2. 2. Prepare
    • Catalogue or register: one source
  3. 3. Do
    • Fill in the details
    • Write quality rules and targets
  4. 4. Report

Catalogue manager or data custodian

Runs the catalogue and the systems behind it, so records can be found, harvested and kept accurate.

Context

Works with tools and standards. Needs to know what any catalogue must expose, whatever the product.

Goals

  • Records that machines can harvest, not only people
  • Conform to the cross-government metadata standard
  • Avoid lock-in to one product

User stories

  • As a catalogue manager or data custodian, I need the exact metadata properties and how they map to the standard, so that records conform first time.
  • As a catalogue manager or data custodian, I need to know what the discoverability service will expect, so that we do not rebuild the feed later.

What gets in the way

  • Guidance and model do not list the same properties
  • Internal-only links break outside the organisation

Success looks like: Every critical data asset record is complete, conforms to the standard and can be harvested as DCAT.

Journey

  1. 1. Learn
    • DCAT and the Metadata Exchange Model
  2. 2. Prepare

Data quality lead or analyst

Brings methods and tools for measuring and improving quality across many assets.

Context

Supports several stewards. Needs a consistent scoring method and tools that work without installing anything.

Goals

  • Score issues the same way across assets
  • Automate measurement across assets
  • Show quality fairly for every group the data describes

User stories

  • As a data quality lead or analyst, I need the government scoring method and tools that apply it, so that priorities are consistent and defensible.
  • As a data quality lead or analyst, I need checks that break results down by group, so that poor quality for some people is not averaged away.

What gets in the way

  • Every team scores issues differently
  • Quality reported as one average

Success looks like: Every critical data asset has scored issues, automated checks and quality reported by group where lawful.

Journey

  1. 1. Learn
    • What counts as an equivalent plan
  2. 2. Prepare

Programme or project lead

Leads a change programme or project that creates, changes, migrates or retires critical data assets.

Context

The programme has its own governance, gates, budget and suppliers. Data asset management can feel like someone else's job until a gate review, migration or handover exposes the gaps.

Goals

  • Pass assurance gates without late data surprises
  • Hand over assets with owners and quality plans in place
  • Avoid creating the next legacy system

User stories

  • As a programme or project lead, I need to know which DAM duties apply to my programme and when, so that they are planned and funded from the business case.
  • As a programme or project lead, I need clear data roles inside my programme team, so that nobody assumes someone else is doing it.

What gets in the way

  • Data owners sit outside the programme and are hard to reach
  • Migration quality problems surface only at cutover

Success looks like: Every critical asset the programme touches has an owner, a catalogue entry and a quality plan before the programme closes.

Journey

  1. 1. Learn
    • Build it in from the start
  2. 2. Prepare
    • Discovery: list the data
  3. 3. Do
    • Test each new asset
  4. 4. Report
    • Make sure it joins the next return
  5. 5. Improve
    • Hand over to business as usual

Commercial or technology lead

Chooses, buys or builds the tools that catalogue, check and govern critical data, and writes the contracts that keep the data yours.

Context

Asked to find a catalogue, quality or master data tool quickly, often with a supplier's suite already on the table.

Goals

  • Buy what the DAM Policy actually needs
  • Prove a tool works with our data before signing
  • Keep the option to leave

User stories

  • As a commercial or technology lead, I need ready-made requirements for each kind of tool, with priorities, so that I can run a request for information without starting from a blank page.
  • As a commercial or technology lead, I need contract clauses that protect our data, so that we are not locked in when the contract ends.

What gets in the way

  • Supplier demonstrations use their data, not ours
  • Bundled suites make it hard to price or leave one part

Success looks like: The tool chosen meets every Must requirement in a proof of concept with your own data, and the contract includes export, exit and data processing terms.

Journey

    • No particular product is required
  2. 2. Prepare
